# 正文图片：压缩、哈希命名与 Git 存储

粘贴、拖入、工具栏选图 → 浏览器压缩 WebP → 计算 SHA-256 → 编辑器预览 → 保存文章时写入 Git。

图片统一位于 `src/assets/article-images/<64位SHA-256>.webp`，不附加文章 ID。多张同名图片由内容区分；压缩结果相同的图片使用同一路径，跨文章复用。

## 使用

无需对象存储账号、上传接口、银行卡或存储密钥。使用既有 Keystatic local / GitHub 模式。

```powershell
npm install
node scripts/patch-keystatic-editor.mjs
npm run dev
```

若开发服务器已经启动，停止并重启，再刷新 Keystatic 页面，以加载编辑器补丁。在线编辑需要部署本次代码，然后刷新编辑器。

粘贴一张或多张图片后等待“正在处理图片”提示消失，再保存文章。也可以使用工具栏图片按钮或拖入图片。图片组件内可独立替换当前图片、编辑替代文本和图片说明。

图片压缩完成前只保存在浏览器内存，保存文章才由 Keystatic 一并写入本地文件或提交到 GitHub。放弃编辑不会产生新图片文件。

正文以 Markdoc 组件记录图片引用，例如：

```markdoc
{% articleImage src="../../../../assets/article-images/完整64位哈希.webp" alt="差动对电路" title="" width=1200 height=800 /%}
```

Astro 构建时读取仓库中的 WebP 文件并生成站点图片地址。不要手工改动哈希文件名或覆盖对应图片内容；替换图片应生成新哈希。

## 压缩规则

- 支持 PNG、JPEG、WebP、AVIF 静态图片；不通过此流程上传 SVG、GIF 或动画。
- 始终在浏览器中转为 WebP，保留透明背景，质量参数为 0.96。最长边超过 3200 像素时等比缩小，小图不放大。
- 原图最大 25 MiB，压缩结果最大 3 MiB。超过范围时会提示缩小后重试。
- 电路图和文字截图使用较高质量参数，仍可能有有损编码变化，保存前可在编辑器检查细小文字。
- 哈希来自最终压缩文件的字节。同一浏览器、相同输入和参数会复用同一路径；不同浏览器或编码器版本不保证输出字节完全一致。

## 共享文件与旧文章

移除或替换文章里的图片、删除文章时，共享哈希图片会保留，避免删除其他文章仍在引用的文件。不自动清理孤立图片；手动清理前需要检查所有文章、草稿、语言版本和分支的引用。

已有 `src/assets/content/body/` 图片和 Markdown 引用继续可用，不会自动迁移或重新压缩。历史上被同名覆盖的不同原图无法靠改文件名恢复，需要重新选择正确图片插入。

只保存压缩结果，不在仓库额外保留原图。图片仍计入 Git 仓库体积与历史；该方案通过压缩和内容去重减少增长，并不提供无限容量。正常备份仓库即可备份图片。

编辑器补丁只对 `src/assets/article-images/` 采用共享文件规则，其他字段继续使用既有 Keystatic 保存逻辑。升级 `@keystatic/core` 前需核对补丁；版本不符或补丁点改变时安装脚本会报错。
